# Image 2.5 知识卡片与课程配图

## 场景流程

1. 从用户材料确定知识来源、目标受众和要传达的一个核心问题。先整理事实与术语，再构图；不要让图像模型自行补齐理论、数据或引用。
2. 路由：简单知识卡、概念插画和装饰配图可以生成；精确比例图、科研图、必须正确的复杂连线或可编辑图形，用 Mermaid/SVG/绘图库等确定性工具。确实需要相关技能时按宿主规则加载。
3. 将内容减到适合目标画幅的层级。保留定义中的关键限定条件；文字过长时拆为用户同意数量的卡片，或生成底图供排版，避免自动扩增图数。
4. 用具体视觉隐喻辅助理解，防止把类比画成字面事实。例如“模型像助手”是教学类比，不把模型画成拥有真实人类记忆器官。
5. 日常卡片偏向 Flare；关系密集或文字难度高时可选 Sunburst，但不把更高质量等同于事实正确。逐字检查核心术语，逐项检查步骤顺序、分组和箭头方向。
6. 有多张时保留色彩角色、标题位置和图例含义。未核实的最新事实先查可靠来源或标出缺项，不能以“模型懂世界”为由跳过核对。

## 提示词组织

“受众 → 需要理解的结论 → 已核实内容及术语原文 → 分区与阅读顺序 → 插画风格 → 避免的误解”。正文和插画说明明确区分。

## 交付标准

交付图片及必要的内容来源/未核实项。图片嵌入幻灯片不等于交付可编辑 PPT；如用户要求 PPT，再按演示文稿工作流创建。

## 执行与模型

本技能将任务组织成适用于 GPT Image 2.5 的工作流；技能本身不提供模型权限，也不保证当前宿主实际使用哪个模型。
- 优先使用当前环境提供的图像生成/编辑工具，遵守其实际参数和系统指令。用户只要提示词或方案时，不调用生成工具。
- 若内置工具不暴露 model 参数，不传入虚构的 model、quality、seed、negative_prompt 或 mask 参数，也不声称已选择 Flare/Sunburst。只在用户要求精确模型时说明这个限制；不能满足硬性模型要求时不要冒充完成。
- 用户已选择支持模型选择的 API/CLI 时，按本技能建议选 Flare 或 Sunburst；参数问题按需读 [模型与接口说明](references/model-notes.md)。不要擅自切换到第三方付费网关或安装额外软件。
- 修改现有图片前先看图。为每张输入标注“编辑目标 / 主体参考 / 风格参考 / 构图参考”，不要因出现图片就一律当成编辑。仅通过当前工具支持的路径或对话图片引用传图，不用文字路径代替实际图片输入。
- 对当前 image_gen 工具：所有目标都有本地路径时用 referenced_image_paths；至少一个目标无路径时用能覆盖全部目标的最小 num_last_images_to_include（最多 5）；两种方式不同时使用。新图且无参考时都省略。若当前环境工具定义不同，以实际定义为准。
- 已获得必要信息就执行，普通审美选择自行合理补全并简短说明。仅当原图缺失、对象指代冲突或关键事实缺失阻碍完成时追问；不要求用户填完表格。
- 未指定数量时做 1 张；按用户指定数量生成，不自行扩成素材套餐。生成后对照任务标准检查；出现明确缺陷可定向修正，默认最多追加 2 轮，用户另有预算/轮数时遵从。服务超时且提交状态不明时先查状态，不重复提交产生可能的重复费用。
- 保留原图和最近通过检查的版本；以通过版本为下一轮依据，避免错误逐轮累积。按宿主要求交付图片并保存用户要求的文件，只有实际获得文件或图片时才称为已生成。
